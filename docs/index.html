👁️ VisioOd API

AI-Powered Ophthalmic Annotation & Differential Diagnosis API

Powered by Composio MCP · Gemini Nano Banana

Overview

VisioOd is a serverless API for ophthalmic image analysis. It runs entirely on GitHub Actions — each endpoint is a workflow that talks to the Composio MCP server to validate, annotate, and diagnose ocular images using Google's Gemini Nano Banana model.

Your frontend stays separate. It calls this API via the GitHub REST API, triggers a workflow, and polls for the result.

Architecture: Frontend → GitHub Actions API (trigger workflow) → VisioOd worker → Composio MCP → Gemini → Result artifact

Authentication

All requests use a GitHub Personal Access Token (PAT) with repo and workflow scopes.

Authorization: token ghp_YOUR_GITHUB_TOKEN
Accept: application/vnd.github+json

The Composio API key is stored as a repository secret: COMPOSIO_API_KEY. Set it in Settings → Secrets and variables → Actions.

Endpoints

POST /vision

Run the ophthalmic annotation pipeline on an uploaded image.

Trigger the workflow

POST https://api.github.com/repos/focusIinks/VisioOd/actions/workflows/vision.yml/dispatches

{
  "ref": "main",
  "inputs": {
    "image_base64": "<base64-encoded image, no data: prefix>",
    "mime_type": "image/png",
    "mode": "all",
    "clinical_context": "45yo male, 3-day redness OD",
    "image_name": "eye_photo.jpg"
  }
}

Inputs

ParameterTypeRequiredDescription
image_base64stringYesBase64-encoded image (no data: prefix)
mime_typestringNoimage/png (default), image/jpeg, image/webp
modestringNoall (default), validate, annotate, diagnose
clinical_contextstringNoPatient history, symptoms, prior findings
image_namestringNoFilename for reference

Pipeline steps (mode: "all")

  1. Validate — checks if the image is ocular. Stops if not.
  2. Annotate — overlays clinical findings (red/yellow/green) on the original image
  3. Diagnose — generates a structured text report with differential diagnoses

Get the result

# Find the latest run
GET https://api.github.com/repos/focusIinks/VisioOd/actions/runs?per_page=1

# Download the result artifact
GET https://api.github.com/repos/focusIinks/VisioOd/actions/runs/{run_id}/artifacts

# Or via the GitHub API zip download endpoint

The result JSON contains: steps.validation, steps.annotation (with image URL), steps.diagnosis (with text report).

POST /tools

List all available Composio MCP tools for the configured API key.

POST https://api.github.com/repos/focusIinks/VisioOd/actions/workflows/tools.yml/dispatches

{
  "ref": "main",
  "inputs": {}
}
GET /runs/{run_id}

Check the status of a workflow run and download its result artifact.

GET https://api.github.com/repos/focusIinks/VisioOd/actions/runs/{run_id}

# Response includes "status" (queued/in_progress/completed) and "conclusion" (success/failure)

Example: Full Flow

# 1. Trigger the vision pipeline
curl -X POST \
  -H "Authorization: token ghp_YOUR_TOKEN" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/focusIinks/VisioOd/actions/workflows/vision.yml/dispatches \
  -d '{
    "ref": "main",
    "inputs": {
      "image_base64": "'"$(base64 -w0 eye.jpg)"'",
      "mime_type": "image/jpeg",
      "mode": "all",
      "clinical_context": "Redness and discharge OD for 3 days"
    }
  }'

# 2. Poll for the run status
curl -s \
  -H "Authorization: token ghp_YOUR_TOKEN" \
  https://api.github.com/repos/focusIinks/VisioOd/actions/runs?per_page=1 \
  | jq '.workflow_runs[0] | {id, status, conclusion}'

# 3. Download the result artifact (once status is "completed")
curl -s \
  -H "Authorization: token ghp_YOUR_TOKEN" \
  https://api.github.com/repos/focusIinks/VisioOd/actions/runs/{RUN_ID}/artifacts \
  | jq '.artifacts[0]'

Adding New Endpoints

To add a new API endpoint, create a new workflow file in .github/workflows/ and a corresponding worker script in src/. The pattern is:

  1. Create src/your-endpoint.js — uses ComposioMcpClient to call MCP tools
  2. Create .github/workflows/your-endpoint.yml — triggers on workflow_dispatch, runs the script, uploads result
  3. Document it in this page and the README
